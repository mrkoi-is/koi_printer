# Koi Printer Studio: 行业竞品分析与架构补全建议

> 针对表单编辑器（Amis/Formily）、专业打印软件（BarTender/Lodop）的行业调研，结合目前 Koi Printer 的现状进行的深度优化方案。

---

## 1. 字段映射与交互方案 (参考低代码自动表单)

在现代低代码平台（如阿里 Formily、百度 Amis、Retool）中，数据模型（Schema）与视图（View）是高度分离且互相映射的。

### 行业最佳实践方案：
1. **统一属性面板 (Unified Inspector)**：
   将所有支持文本展示的组件（Text, Barcode, QR Code），在右侧面板的“数据内容”区域统一重构为三种模式供用户切换：
   *   **静态文本 (Static)**：纯固定文字，如“Mr.Koi 专卖店”。
   *   **单一变量 (Variable)**：完全绑定某个业务字段。UI 呈现为一个可搜索的**级联下拉框 (Cascader)**。用户选择 `商品 -> 价格 (items.price)`，系统自动处理关联。
   *   **混合表达式 (Expression/Template)**：允许用户输入 `共计：{{fee.total}} 元`。输入框下方提供一个**“插入变量”**的快捷按钮，点击后弹出变量树，选中即可插入占位符，避免手写导致语法错误。

2. **视图与数据双向提示 (Hover Highlight)**：
   当鼠标在左侧“数据源”面板悬停在某个字段（如 `waybillNo`）上时，中间画布 (Canvas) 里所有绑定了该字段的组件应当发光高亮。反之亦然。

## 2. 现有组件库的完整度盘点 (Component Completeness)

对比成熟的商业打单软件，我们目前的 AST (抽象语法树) 核心库其实非常完整，但**可视化编辑器的 UI 暴露层存在缺失**。

### ✅ 已完整具备的组件
*   **基础排版**：文本 (Text)、多列栅格 (Row/Column)、分割线 (Divider)、空白留白 (Spacer)。
*   **条码图形**：二维码 (QR Code)、一维码 (Barcode)。
*   **硬件指令**：切纸 (Cut)。

### ❌ 编辑器 UI 急需补充的核心组件
1. **列表循环组件 (ForEach / List Table)**：**[最高优先级]**
   *   **现状**：底层的 `KoiTemplateEngine` 支持 Mustache 语法的 `{{#items}}...{{/items}}` 循环渲染。
   *   **缺失**：编辑器 UI 缺少对应的组件。我们需要在左侧物料盘增加一个“商品明细/列表循环”组件。拖入后，它是一个特殊的容器组件（高亮虚线框），用户需要先给它绑定一个 Array 数据源（如 `items`），然后在里面定义**单行 (Row)** 的样式。
2. **本地图片/Logo 组件 (Image)**：
   *   目前底层有 `KoiTicketImageElement`，但编辑器里没有暴露上传按钮。需要引入图片上传功能，并在 JSON 序列化时转为 Base64 存储。
3. **面单绝对定位组件 (Label Components)**：
   *   目前只支持小票的流式布局（自上而下）。未来如果要支持面单（TSPL），我们需要引入带有 `(x, y)` 坐标的组件，允许八向拖拽放大缩小。

## 3. 现有模板如何选择与加载 (Template Gallery)

为了让用户能快速复用我们已有的行业模板（如寄件联、收件联、简单收据），我们需要在编辑器引入**“模板大厅 (Template Gallery)”**机制。

### 实现方案
1. **JSON 持久化引擎**：
   将我们在 `example` 中用 Dart 代码写死的 `KoiSenderTicketTemplate` 等默认模板，全部转换为 `.json` 文件格式并存入资产目录。
2. **欢迎大厅 (Welcome Modal)**：
   * 当用户打开编辑器时，首先弹出一个全屏的模板选择对话框（类似 Figma / Word 的启动页）。
   * 提供选项卡：【空白模板】、【快递物流模板库】、【餐饮零售模板库】。
   * 用户点击某一个缩略图（如“标准寄件联”），系统读取对应的 JSON，通过反序列化转化为 `EditorState` 的 `_elements` 数组并渲染出画布。
3. **顶部快速切换**：
   在顶部工具栏的左上角增加一个“新建/打开模板”的文件夹图标，随时唤出模板大厅。
